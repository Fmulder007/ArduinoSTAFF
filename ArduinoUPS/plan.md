# ArduinoUPS — план макета

**Статус:** рабочий план, распиновка предложена к согласованию.  
**Репозиторий:** `Fmulder007/ArduinoSTAFF`  
**Каталог проекта:** `ArduinoUPS/`  
**Плата:** классическая Arduino Nano на ATmega328P, 16 МГц.

## 1. Цель первого макета

Сначала сделать только генератор двух чередующихся управляющих сигналов для простого двухтактного меандра 50 Гц.

В первом испытательном варианте:
- генерация выполняется аппаратным Timer1;
- режим Timer1 — Normal, предделитель 8;
- выходы переключаются через прямую работу с регистром порта, без `digitalWrite()`;
- два плеча никогда не должны получать команду включения одновременно;
- пауза между активными интервалами встроена в последовательность событий Timer1;
- длительность паузы для первого испытания — 10% полупериода;
- отдельный вход RUN включает и выключает генератор;
- отдельный выход DRIVER_EN разрешает работу внешних драйверов.

Пока не реализуются контроль сети и АКБ, заряд, реле, измерение тока/температуры и расширенная система защит. Эти функции относятся к следующим этапам. Базовое состояние «выключено» при сбросе микроконтроллера обязательно сохраняется.

## 2. Резервирование выводов Nano

Чтобы оставить возможность добавить энкодер, дисплей, меню, связь и программирование, следующие выводы не занимаем управляющими сигналами ИБП:

| Выводы Nano | Назначение / резерв |
|---|---|
| D0 / RX, D1 / TX | USB-UART, загрузчик и последовательная отладка |
| D2 / INT0, D3 / INT1 | Энкодер; оба внешних прерывания остаются свободными |
| A4 / SDA, A5 / SCL | Шина I²C для дисплея и других устройств |
| D10–D13 | Резерв всей шины SPI: D10 — SS, D11 — MOSI/COPI, D12 — MISO/CIPO, D13 — SCK |
| RESET и разъём ICSP | Не использовать как обычные сигналы проекта |

D11–D13 также используются интерфейсом ICSP для внутрисхемного программирования. D10 не является линией MOSI/MISO/SCK разъёма ICSP, но резервируется вместе с ними, чтобы оставить свободной всю шину SPI.

## 3. Предлагаемая распиновка макета

Предлагаю отдать под управление ИБП выводы D4–D7. На ATmega328P это PD4–PD7 — четыре соседних бита одного регистра PORTD. Можно менять состояния всех трёх выходов одной операцией с маской, не затрагивая D0–D3.

| Arduino Nano | Порт МК | Сигнал | Направление | Активный уровень |
|---|---|---|---|---|
| D4 | PD4 | RUN | Вход | HIGH — запрос работы |
| D5 | PD5 | DRIVER_EN | Выход | HIGH — драйверы разрешены |
| D6 | PD6 | OUT_A | Выход | HIGH — первое плечо включено |
| D7 | PD7 | OUT_B | Выход | HIGH — второе плечо включено |

Для входа RUN предусмотреть внешний резистор подтяжки к GND, чтобы при разомкнутом входе читался LOW. Для DRIVER_EN и входов управления драйверов предусмотреть аппаратную подтяжку к GND: во время сброса, загрузчика и до настройки DDR выводы МК высокоомные.

Выводы D4–D7 пока считаются **предлагаемым**, а не окончательно утверждённым назначением. Остальные свободные выводы Nano не занимать без необходимости.

## 4. Временная последовательность генератора

Частота тактирования МК — 16 МГц. При предделителе Timer1 = 8 частота счётчика равна 2 МГц, один отсчёт — 0,5 мкс.

Один полупериод выходного сигнала — 10 мс:
- активное состояние плеча — 9 мс, 18 000 отсчётов;
- состояние ALL_OFF — 1 мс, 2 000 отсчётов.

Полный период — 20 мс, 40 000 отсчётов, то есть 50 Гц.

Порядок повторяющихся интервалов:

1. OUT_A = HIGH, OUT_B = LOW — 9 мс.
2. OUT_A = LOW, OUT_B = LOW — 1 мс.
3. OUT_A = LOW, OUT_B = HIGH — 9 мс.
4. OUT_A = LOW, OUT_B = LOW — 1 мс.
5. Повтор с первого пункта.

Включение противоположного плеча допускается только после интервала ALL_OFF. OUT_A и OUT_B не должны одновременно становиться HIGH ни при запуске, ни при переключении, ни при остановке.

Для Timer1 предварительно выбран режим Normal. Следующее событие сравнения планируется прибавлением длительности интервала к предыдущему значению OCR1A, а не отсчётом задержки от момента выполнения обработчика. Это уменьшает накопление временной ошибки от задержек входа в прерывание.

## 5. Последовательность запуска после подачи питания

Задача последовательности — исключить случайные импульсы при включении питания, выполнении загрузчика и инициализации скетча. Генерация не должна начинаться только потому, что RUN уже оказался в HIGH при старте.

1. **Питание подано / выполняется загрузчик.**  
   Выводы МК ещё могут быть входами с высоким сопротивлением. Внешние подтяжки удерживают DRIVER_EN, OUT_A и OUT_B в LOW. RUN при отсутствии команды также удерживается в LOW.

2. **Начало setup().**  
   Сначала записать LOW в выходные разряды PORTD для PD5–PD7, затем настроить PD5–PD7 как выходы. PD4 настроить как вход без внутренней подтяжки; уровень RUN задаётся внешней схемой. Немедленно оставить DRIVER_EN, OUT_A и OUT_B в LOW.

3. **Таймер остановлен.**  
   Остановить Timer1, запретить его прерывание сравнения, очистить ожидающий флаг сравнения, сбросить счётчик и подготовить начальное состояние ALL_OFF. На этом этапе ни один импульс не формируется.

4. **Пауза после инициализации — 1000 мс.**  
   Выдержать секунду для завершения переходных процессов питания и инициализации платы. DRIVER_EN, OUT_A и OUT_B всё это время остаются LOW, Timer1 остановлен.

5. **Проверка исходного состояния RUN.**  
   После паузы дождаться устойчивого LOW на RUN. Если при включении RUN уже находится в HIGH, не запускать генератор: сначала вход должен вернуться в LOW. Это требует явного нового перехода LOW → HIGH.

6. **Подтверждение команды запуска.**  
   Принять только устойчивый переход RUN из LOW в HIGH; предварительно предусмотреть программную фильтрацию дребезга входа (ориентир 20–50 мс).

7. **Разрешение драйверов.**  
   OUT_A и OUT_B оставить в LOW. Установить DRIVER_EN в HIGH и выдержать 1 мс, чтобы внешние драйверы успели перейти в рабочее состояние при закрытых плечах.

8. **Старт первого полупериода.**  
   Обнулить/подготовить временную базу Timer1, установить начальное состояние OUT_A = HIGH, OUT_B = LOW и запустить расписание событий. Первое активное плечо всегда A; далее последовательность идёт строго A → ALL_OFF → B → ALL_OFF.

9. **Остановка по RUN = LOW.**  
   Остановить расписание Timer1, запретить его прерывание, принудительно установить OUT_A = LOW и OUT_B = LOW, затем установить DRIVER_EN = LOW. Для следующего запуска снова потребуется подтверждённое состояние LOW и новый переход LOW → HIGH.

## 6. Что проверить осциллографом

До подключения силовой части проверить только логические сигналы:
- после подачи питания и во время паузы 1000 мс на OUT_A, OUT_B и DRIVER_EN нет HIGH;
- при RUN, оставленном в HIGH во время включения, самопроизвольного старта нет;
- старт происходит только после LOW → HIGH;
- на OUT_A и OUT_B чередуются импульсы с заданными длительностями;
- между импульсами всегда присутствует интервал ALL_OFF;
- одновременного HIGH на OUT_A и OUT_B нет;
- период повторения последовательности равен 20 мс;
- при RUN = LOW оба выхода становятся LOW и DRIVER_EN отключается.

## 7. Отложено на следующие этапы

После успешной проверки генератора отдельно обсудить и спроектировать:
- измерение напряжения АКБ и сети;
- управление зарядным устройством;
- переключение сети и инвертора;
- контроль тока, температуры и перегрузки;
- дополнительные аппаратные и программные защиты;
- индикацию, экран, меню и энкодер.

## 8. Правило ведения проекта

Вся работа над этим ИБП — обсуждения, исследования, расчёты, исходники, тесты и документация — ведётся только внутри каталога `ArduinoUPS/` репозитория `Fmulder007/ArduinoSTAFF`. Остальные каталоги и проекты репозитория не изменять в рамках ArduinoUPS.
