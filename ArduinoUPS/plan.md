# ArduinoUPS — RP2040-Zero / PIO + журнал OLED

**Статус:** испытательная версия: четыре выхода PIO, RUN, батарейная блокировка, USB Serial и журнал на OLED.  
**База:** ветка \`arduino-ups-rp2040-pio\`, перенесённая из \`arduino-ups-four-output-driver\`.  
**Текущая ветка:** \`arduino-ups-rp2040-log-display\`.  
**Плата:** Waveshare RP2040-Zero, RP2040.  
**Среда:** Arduino IDE + Arduino-Pico core by Earle F. Philhower.

## 1. Цель версии

Сохранить уже проверенный PIO-генератор и добавить:
- вход RUN;
- измерение напряжения АКБ;
- общий байт запретов \`generatorBlockFlags\`;
- защёлку низкого напряжения АКБ и восстановление;
- единый журнал событий на USB Serial и OLED 128×32.

Дисплей пока показывает только журнал. Часы DS1307 пока не подключены: дата/время формируются заглушкой \`--.--.---- --:--:--\`.

Файловый журнал во Flash и USB Mass Storage не используются.

## 2. Распиновка

| RP2040-Zero | Назначение |
|---|---|
| GP0 | DRIVER_A_H — верхнее плечо драйвера A |
| GP1 | DRIVER_A_L — нижнее плечо драйвера A |
| GP2 | DRIVER_B_H — верхнее плечо драйвера B |
| GP3 | DRIVER_B_L — нижнее плечо драйвера B |
| GP4 | RUN — HIGH: генерация нужна; LOW: сеть появилась |
| GP6 | I2C1 SDA — OLED сейчас, DS1307 позднее |
| GP7 | I2C1 SCL — OLED сейчас, DS1307 позднее |
| GP26 | ADC0 — измерение напряжения АКБ |

GP0–GP3 управляются одним PIO State Machine командой \`SET PINS\`. GP4 читается только \`updateRunStatus()\`.

Энкодер и DS18B20 пока не подключаются. GP10–GP13 остаются свободными под будущую периферию.

## 3. Генератор PIO

Параметры сохранены из четырёхвыходной AVR-ветки:

- частота — 50 Гц;
- полный период — 20 мс;
- активный импульс верхнего плеча — 9 мс;
- общее межполупериодное окно — 1 мс;
- защитная пауза внутри каждого драйвера — 50 мкс;
- остаточное межполупериодное ожидание — 900 мкс.

Частота PIO — 2,5 МГц, один цикл — 0,4 мкс. При \`clk_sys = 125 МГц\` используется целый делитель 50.

PIO самостоятельно выполняет все переключения. CPU не обслуживает фронты. I2C, OLED, Serial, АЦП и обработка RUN не меняют временную последовательность PIO.

PIO проверяет внутренний STOP-флаг только на границе полного периода A+B:
- STOP=0 — разрешить следующий период;
- STOP=1 — закончить текущий период и остаться в NORMAL.

## 4. Таблица состояний выходов

Бит 0 = GP0/A_H, бит 1 = GP1/A_L, бит 2 = GP2/B_H, бит 3 = GP3/B_L.

| Состояние | Биты GP3…GP0 | Включённые плечи |
|---|---:|---|
| NORMAL | 1010 | A_L + B_L |
| A_PREPARE | 1000 | B_L |
| A_ACTIVE | 1001 | B_L + A_H |
| B_PREPARE | 0010 | A_L |
| B_ACTIVE | 0110 | A_L + B_H |
| ALL_OFF | 0000 | все выключены |

Ни в одном состоянии верхнее и нижнее плечо одного драйвера не включаются одновременно. Все четыре бита изменяются одной командой PIO.

## 5. RUN и разрешение генерации

- RUN=HIGH означает запрос генерации.
- RUN=LOW должен сохраняться непрерывно 5000 мс, чтобы сеть считалась подтверждённой.
- Кратковременный RUN=LOW менее 5 секунд не снимает запрос генерации.
- При подтверждении сети запрос генерации снимается.
- Генерация разрешена только если \`generatorRunRequest == true\` и \`generatorBlockFlags == 0\`.
- Если запрет появился во время полного периода, PIO заканчивает текущий период A+B и остаётся в NORMAL.
- Если запрос снова разрешён, PIO начинает следующий полный период.

## 6. Байт запретов generatorBlockFlags

\`generatorBlockFlags\` — общая маска типа \`uint8_t\`:
- \`0x00\` — запретов нет, генерация может работать при RUN=HIGH;
- любое ненулевое значение — генерация запрещена;
- каждый модуль меняет только принадлежащий ему бит.

| Маска | Причина |
|---:|---|
| 0x01 | Низкое напряжение аккумулятора |
| 0x02 | Перегрев |
| 0x04 | Перегрузка |
| 0x08 | Неисправность/недопустимое состояние сети |
| 0x10 | Неисправность датчика |
| 0x20–0x80 | Резерв |

В этой версии реализован батарейный бит 0x01. Остальные причины зарезервированы под будущие модули.

Батарейная логика:
- напряжение хранится в сотых долях вольта (\`1234 = 12,34 В\`);
- измерение выполняется раз в секунду;
- каждый результат — среднее 16 измерений;
- достижение нижнего порога защёлкивает \`BLOCK_BATTERY_LOW\`;
- само по себе повышение напряжения после снятия нагрузки не снимает защёлку;
- снятие защёлки разрешено только при подтверждённой сети и достижении порога восстановления;
- если оба порога равны нулю, батарейная отсечка временно отключена для макета;
- неправильно заданные пороги оставляют батарейную блокировку установленной.

АЦП RP2040 настраивается на 12 бит (0…4095). Используется номинальная опора 3300 мВ и делитель 330 кОм / 10 кОм. Пересчёт выполняется целочисленно; промежуточное умножение использует \`uint64_t\`. Коэффициент опоры нужно откалибровать по конкретной плате и мультиметру до эксплуатации.

## 7. Журнал событий

Все сообщения создаются одной функцией \`logEvent()\` и одновременно направляются:
- в USB CDC Serial;
- в буфер текстового журнала OLED.

Скорость, передаваемая в \`Serial.begin()\`, — 9600. Для USB CDC это параметр линии виртуального COM-порта; физический USB-поток не ограничивается UART-скоростью.

Дата/время пока выдаются заглушкой \`--.--.---- --:--:--\`. При добавлении DS1307 заменяется только функция \`getLogTimestamp()\`.

Логируются только изменения:
- запрос генерации и подтверждение сети;
- появление каждой причины блокировки;
- переход общей маски из 0 в ненулевое значение;
- восстановление напряжения и снятие батарейной защёлки;
- снятие отдельных причин запрета;
- переход общей маски обратно в 0.

Повторяющиеся сообщения в каждом проходе \`loop()\` не печатаются.

Примеры сообщений:

\`\`\`text
--.--.---- --:--:-- [BOOT] ArduinoUPS RP2040 запущен
--.--.---- --:--:-- [RUN] Запрошена генерация
--.--.---- --:--:-- [BLOCK] flags=0x01, Низкое напряжение аккумулятора
--.--.---- --:--:-- [BLOCK] flags=0x01, Генерация запрещена
--.--.---- --:--:-- [RUN] Сеть подтверждена
--.--.---- --:--:-- [RECOVERY] Напряжение аккумулятора восстановлено
--.--.---- --:--:-- [CLEAR] flags=0x00, Блокировка по низкому напряжению снята
--.--.---- --:--:-- [ALLOW] flags=0x00, Все запреты генерации сняты
\`\`\`

Событие обрабатывается только при изменении состояния. Если USB Serial Monitor не подключён, программа не ждёт его открытия; журнал продолжает поступать на OLED.

## 8. OLED 128×32

- Контроллер: SSD1306 128×32.
- I2C: второй аппаратный интерфейс RP2040, \`Wire1\`, GP6/GP7.
- Частота I2C: 100 кГц.
- Адрес при старте проверяется сначала 0x3C, затем 0x3D.
- Библиотека: U8g2, конструктор SSD1306 128×32, полный буфер, второй аппаратный I2C.
- Шрифт: \`u8g2_font_5x8_t_cyrillic\`, поддержка русского текста.
- На дисплее четыре текстовые строки высотой 8 пикселей.
- Длинные сообщения автоматически переносятся на следующие строки на границах UTF-8 символов.
- Новые строки добавляются снизу, старые уходят вверх.
- В RAM хранится 20 последних строк для формирования прокрутки.
- Обновление дисплея выполняется только после появления новых сообщений.
- Если OLED не обнаружен, журнал Serial продолжает работать.

U8g2 устанавливается через Arduino IDE → Library Manager → \`U8g2\` (автор Oliver Kraus).

## 9. Целочисленная арифметика

В пользовательском коде не использовать \`float\` и \`double\`.

- напряжение АКБ — сотые доли вольта;
- частота — целое число герц;
- временные интервалы — целое число тактов PIO или миллисекунд;
- температура будущего DS18B20 — сотые доли градуса;
- причины блокировки — байтовая маска;
- коэффициенты делителей и опорные напряжения — целые числа;
- промежуточное умножение при расчёте напряжения — \`uint64_t\`.

## 10. Что пока не реализовано

- DS1307 и реальная дата/время;
- энкодер;
- DS18B20;
- меню и другие экраны;
- реле зарядки;
- остальные аппаратные защиты;
- файловый журнал во Flash;
- USB Mass Storage.

## 11. Проверка на стенде

1. Собрать скетч для Waveshare RP2040-Zero с CPU 125 MHz.
2. Установить библиотеку U8g2 через Library Manager.
3. Проверить GP0–GP3 осциллографом без силовых драйверов.
4. Убедиться, что PIO-сигналы сохранили прежнюю форму и период.
5. Проверить вход RUN: HIGH запускает, LOW менее 5 секунд не останавливает.
6. Удерживать RUN=LOW 5 секунд: генератор завершает полный A+B и возвращается в NORMAL.
7. Проверить русские сообщения в Serial Monitor и на OLED.
8. Временно задать тестовые пороги батареи и проверить установку/снятие \`BLOCK_BATTERY_LOW\`.
9. Проверить, что OLED-обновление и Serial не нарушают временную последовательность GP0–GP3.

Силовые драйверы подключать только после проверки логических сигналов и защитных интервалов.
