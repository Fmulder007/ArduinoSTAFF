# ArduinoUPS — план макета

**Статус:** экспериментальная ветка с четырёхвыходным драйвером и собственной временной базой Timer1.  
**Репозиторий:** Fmulder007/ArduinoSTAFF  
**Каталог проекта:** ArduinoUPS/  
**Плата:** классическая Arduino Nano, ATmega328P, 16 МГц.

## 1. Цель текущего этапа

Разработать испытательный генератор двухтактного ИБП с двумя драйверами IRFZ44N. Каждый драйвер имеет два независимых управляющих входа: верхний (заряд затвора силового MOSFET) и нижний (разряд затвора силового MOSFET).

Основные правила:
- четыре управляющих сигнала размещены на PD4–PD7 одного регистра PORTD;
- допустимые комбинации выходов заранее заданы таблицей;
- верхнее и нижнее плечи одного драйвера никогда не включаются одновременно;
- нормальное состояние — оба нижних плеча включены, оба верхних выключены;
- генерация состоит из полных симметричных периодов A+B по 20 мс;
- разрешение генерации проверяется только на границе полного периода;
- если запрет появился внутри периода, текущая пара A+B завершается, следующий период не запускается;
- Timer1 задаёт события силового автомата и одновременно служит собственной временной базой;
- фоновые задачи выполняются небольшими порциями в основном цикле;
- прикладной код проекта не использует cli() и не блокирует прерывания.

## 2. Распределение выводов Nano

Четыре управляющих сигнала занимают старшую тетраду PORTD — PD4–PD7. Чтобы освободить PD4, кнопку энкодера переносим с D4 на A2. Каналы энкодера A/B остаются на D2/D3.

| Вывод Nano | Порт МК | Назначение |
|---|---|---|
| A0 | PC0 | RUN, вход датчика сети |
| A1 | PC1 | PERMIT, резерв входа разрешения |
| A2 | PC2 | Кнопка энкодера, перенос с D4 |
| A6 | ADC6 | Измерение напряжения АКБ |
| D2 | PD2 | Энкодер A |
| D3 | PD3 | Энкодер B |
| D4 | PD4 | DRIVER_A_H — верхнее плечо драйвера A |
| D5 | PD5 | DRIVER_A_L — нижнее плечо драйвера A |
| D6 | PD6 | DRIVER_B_H — верхнее плечо драйвера B |
| D7 | PD7 | DRIVER_B_L — нижнее плечо драйвера B |
| D8 | PB0 | CHARGE_RELAY, пока всегда LOW |
| D9 | PB1 | Свободный цифровой вывод |
| D0/D1 | PD0/PD1 | UART/загрузка; не использовать для драйверов |
| A4/A5 | PC4/PC5 | I²C |
| D10–D13 | PORTB | SPI/ICSP, резерв |

D4–D7 физически являются соседними битами одного PORTD. Одна запись в PORTD меняет все четыре управляющих сигнала практически одновременно. Код сохраняет PD0–PD3 маской.

В рабочем коде фоновые задачи не должны изменять PORTD. В частности, нельзя во время работы генератора использовать digitalWrite() или включать внутренние подтяжки на D0–D3, если функция ядра выполняет read-modify-write всего PORTD. Входы энкодера следует настроить один раз при инициализации; далее только читать PIN-режим.

D5 больше не является отдельным DRIVER_EN. D6/D7 больше не являются одиночными OUT_A/OUT_B: все четыре вывода независимо управляют плечами обоих драйверов.

## 3. Таблица выходных состояний PORTD

Назначение битов:
- PD4 — A_H;
- PD5 — A_L;
- PD6 — B_H;
- PD7 — B_L.

Значения ниже записаны как старшая тетрада PORTD в порядке PD7…PD4:

| Состояние | A_H | A_L | B_H | B_L | PORTD PD7…PD4 |
|---|---:|---:|---:|---:|---:|
| Нормальное | 0 | 1 | 0 | 1 | 1010 = 0xA0 |
| Подготовка A | 0 | 0 | 0 | 1 | 1000 = 0x80 |
| Импульс A | 1 | 0 | 0 | 1 | 1001 = 0x90 |
| Подготовка B | 0 | 1 | 0 | 0 | 0010 = 0x20 |
| Импульс B | 0 | 1 | 1 | 0 | 0110 = 0x60 |
| Аварийное ALL_OFF | 0 | 0 | 0 | 0 | 0000 = 0x00 |

В таблице нет комбинаций A_H+A_L или B_H+B_L. В коде значения хранятся во Flash. Запись шаблона меняет PORTD одной операцией, сохраняя младшую тетраду.

На затворе каждого управляющего 2N7002 требуется резистор 10 кОм к GND. У верхнего BSS84 обязателен отдельный резистор затвор–исток к источнику +8 В, чтобы закрывать BSS84 при выключенном управляющем 2N7002. У каждого силового IRFZ44N нужен собственный резистор затвор–исток: при RESET все управляющие 2N7002 закрыты, поэтому нельзя полагаться только на нижние ключи для разряда силовых затворов.

## 4. Временная последовательность генератора

Timer1 работает в Normal mode с предделителем 8. При 16 МГц его частота равна 2 МГц, один тик — 0,5 мкс.

Для настроек 50 Гц и общего dead time 10%:
- период — 20 мс, 40 000 тиков;
- полупериод — 10 мс, 20 000 тиков;
- активный импульс каждого верхнего плеча — 9 мс, 18 000 тиков;
- общее межполупериодное окно — 1 мс, 2 000 тиков;
- защитная пауза одного драйвера — 50 мкс, 100 тиков;
- остаток межполупериодного окна после двух защитных пауз — 900 мкс, 1 800 тиков.

Порядок одного периода:
- t=0: выключить A_L;
- t=50 мкс: включить A_H;
- A_H работает 9 мс;
- t=9,05 мс: выключить A_H;
- t=9,10 мс: включить A_L, вернуть A в нормальное состояние;
- t=10 мс: выключить B_L;
- t=10,05 мс: включить B_H;
- B_H работает 9 мс;
- t=19,05 мс: выключить B_H;
- t=19,10 мс: включить B_L, вернуть B в нормальное состояние;
- t=20 мс: граница нового периода и единственная проверка разрешения.

Каждый переход выполняется парой событий Timer1: выключение прежнего плеча, затем через заданную защитную паузу включение следующего. Все временные интервалы — целые количества тиков Timer1. В рабочем коде нет расчётов времени с float.

## 5. Разрешение генерации и обработка RUN

Физический вход RUN читает только updateRunStatus() в основном цикле. Она обновляет один байт runControlFlags:
- RUN_FLAG_GENERATOR_REQUEST — RUN=HIGH, генерация запрошена;
- RUN_FLAG_MAINS_CONFIRMED — RUN=LOW непрерывно 5 секунд;
- RUN_FLAG_STARTUP_READY — прошла стартовая выдержка и получено первое измерение АКБ.

Timer1 физический RUN не читает. На GEN_PERIOD_BOUNDARY он проверяет только generatorBlockFlags и соответствующие биты runControlFlags.

Внутри периода A+B разрешения не проверяются. Если RUN=LOW или generatorBlockFlags меняются во время периода, текущие импульсы A и B заканчиваются полностью. На следующей границе новый период либо запускается, либо генератор остаётся в нормальном состоянии.

RUN=LOW менее 5 секунд не останавливает уже работающий генератор. При подтверждении сети запрос генерации снимается, но только на границе завершённого периода.

## 6. GyverCore и собственная временная база

GyverCore используется только как минимальная среда входа в setup()/loop() и C++-окружение. Его системный таймер и аппаратная инициализация отключены.

**Обязательные настройки платы в Arduino IDE:**
- Tools → System timer → Disable;
- Tools → Initialization → Disable.

Первая настройка задаёт макрос _GYVERCORE_NOMILLIS и убирает обработчик TIMER0_OVF вместе с функциями millis()/micros(). Вторая задаёт _GYVERCORE_NOINIT: main.cpp пропускает вызов init(), поэтому GyverCore не настраивает периферию и не выполняет свою стартовую критическую секцию с cli(). В скетче есть проверки времени компиляции: без обеих настроек сборка завершается ошибкой.

Вся используемая периферия настраивается непосредственно в setup(). Timer0 останавливается, Timer1 полностью настраивается проектом, АЦП настраивается напрямую через регистры. После полной настройки GPIO, АЦП и Timer1 функция setup() один раз вызывает sei(), чтобы разрешить прерывания. В прикладном коде ArduinoUPS нет вызовов cli().

Timer1 используется одновременно как:
- источник точных событий силового автомата;
- источник прошедшего времени;
- основа собственного аналога системных миллисекунд.

После каждого события Timer1 добавляет к системному времени известное количество прошедших тиков. Между событиями текущий момент уточняется чтением свободно бегущего TCNT1. Поэтому в режиме ожидания Timer1 может выдавать одно событие раз в 20 мс, но основной цикл всё равно получает текущее время внутри этого интервала. Отдельного прерывания каждую миллисекунду нет.

Для согласованного чтения многобайтового времени используется однобайтовый systemTimeSequence — seqlock:
1. основной цикл читает номер версии;
2. читает миллисекунды, дробную часть и TCNT1;
3. повторно читает версию;
4. если версия изменилась или была нечётной, снимок отбрасывается, чтение повторяется на следующем проходе loop().

Так читаются 32-разрядные данные без cli() и без ожидания внутри цикла.

**Ограничение:** main.cpp GyverCore пока остаётся в качестве простого входного цикла setup()/loop(). Проект не использует его периферийную и временную инициализацию. Полное удаление оставшейся оболочки main.cpp и отдельная конфигурация avr-gcc — самостоятельный этап, если решим отказаться от Core целиком.

## 7. Кооперативный диспетчер фоновых задач

Timer1 имеет высший приоритет по времени переключения силовых выходов. Основной loop() не управляет ключами; он выполняет по одной небольшой фоновой задаче за проход.

В текущем прототипе диспетчер по очереди обслуживает:
- чтение физического RUN и обновление программных флагов;
- обслуживание АЦП;
- проверку завершения стартовой выдержки;
- снятие батарейной защёлки при подтверждённой сети и достаточном напряжении.

Будущие задачи (энкодер, кнопки, меню, дисплей, температура, вентилятор, связь) добавляются отдельными короткими шагами. Длительные операции разбиваются на продолжения в последующих проходах. Timer1 может прервать фоновую задачу в любой момент, после чего основной цикл продолжится с того места, где был прерван.

Измерение АКБ также разбито на шаги:
- один проход запускает преобразование АЦП;
- другие проходы проверяют его завершение;
- один отсчёт добавляется в сумму;
- следующий отсчёт запускается не ранее чем через 2 мс;
- после 16 отсчётов рассчитывается напряжение и обновляется BLOCK_BATTERY_LOW.

Во время работы фоновой задачи нельзя использовать длинные delay(), ожидания в циклах, блокирующие операции дисплея/связи или длительные участки с запрещёнными прерываниями. Для будущих библиотек необходимо проверять, не отключают ли они прерывания и не используют ли Timer1.

## 8. Обмен данными между основным циклом и ISR без cli()

Общие переменные разделяются по принципу одного писателя:
- runControlFlags — пишет только основной цикл, Timer1 читает;
- generatorBlockFlags — причины запрета обновляют фоновые модули основного цикла, Timer1 читает;
- многобайтовые измерения АКБ остаются в основном цикле и не читаются из ISR;
- системное время обновляет Timer1, основной цикл читает его по systemTimeSequence.

Однобайтовые флаги ATmega328P читаются и записываются атомарно. Для 16/32-разрядных значений, которые в будущем потребуются одновременно в основном цикле и ISR, применяется версия/снимок или обмен через готовый буфер. Нельзя читать половину значения из одного обновления, а половину из следующего.

Прикладной код ArduinoUPS не вызывает cli() и не включает вложенные прерывания. Сторонние библиотеки перед использованием проверяются на критические секции и длительные ISR.

## 9. Защита от ошибочного состояния и зависания

Каждое нормальное переходное состояние автомата заканчивается следующим событием Timer1; бесконечных ожиданий внутри автомата нет.

Если автомат попал в неизвестное состояние:
1. Все четыре управляющих выхода устанавливаются в LOW.
2. Через защитную паузу включаются оба нижних плеча.
3. Автомат возвращается к нормальному состоянию и ждёт следующую границу периода.

Это восстанавливает выходы при программной ошибке состояния, пока Timer1 и процессор продолжают исполнять ISR.

Аппаратный watchdog в этой версии ещё не включён. Он должен быть добавлен отдельно и проверен с конкретным загрузчиком Nano. Обычный основной цикл не может гарантированно восстановить систему, если процессор полностью завис или Timer1 перестал обслуживать события.

## 10. Инициализация и стендовая проверка

В начале setup():
- все PD4–PD7 сначала устанавливаются в LOW и переводятся в OUTPUT;
- затем одной записью устанавливается нормальное состояние 0xA0;
- D8 устанавливается в LOW и переводится в OUTPUT;
- A0 настраивается как вход без внутренней подтяжки;
- Timer0 останавливается;
- Timer1 перенастраивается в Normal mode, устанавливается Compare A и предделитель 8;
- АЦП настраивается на внутреннюю опору 1,1 В и делитель /128.

После запуска Timer1 система начинает собственный отсчёт времени. Первое измерение АКБ выполняется пошагово; генератор не запускается, пока не прошла стартовая выдержка 1000 мс и не закончено первое измерение.

До подключения силовой части проверить:
- в Arduino IDE выбрано Tools → System timer → Disable;
- при RESET/Hi-Z внешние резисторы удерживают управляющие 2N7002 закрытыми;
- после инициализации PORTD = 0xA0 на PD7…PD4;
- во всех строках таблицы нет одновременного HIGH верхнего и нижнего плеча одного канала;
- A_H и B_H дают импульсы по 9 мс со сдвигом 10 мс и периодом 20 мс;
- защитные паузы между верхним и нижним плечами не меньше 50 мкс;
- джиттер на фронтах сравнить с предыдущей сборкой, в которой работал системный тик Timer0;
- запрет, появившийся посреди периода, не прерывает текущую пару A+B;
- после остановки сохраняется нормальное состояние 0xA0;
- Timer0 не генерирует регулярных прерываний;
- измерение АКБ выполняется в фоне отдельными преобразованиями, а не блокирующим пакетом;
- D8/CHARGE_RELAY остаётся LOW.

До проверки четырёх логических сигналов осциллографом силовые IRFZ44N и нагрузку не подключать. Первый этап — только низковольтный макет драйверов.

## 11. Общий байт запретов генерации

Используется одна глобальная переменная generatorBlockFlags типа uint8_t:

- значение 0 — причин запрета нет, генерация может работать при RUN=HIGH;
- любое ненулевое значение — генерация запрещена;
- каждый модуль устанавливает и снимает только принадлежащий ему бит операциями OR и AND с инверсной маской;
- модуль не должен обнулять весь байт, потому что одновременно могут действовать несколько причин запрета.

Назначение битов:

| Маска | Причина |
|---:|---|
| 0x01 | Низкое напряжение аккумулятора |
| 0x02 | Перегрев |
| 0x04 | Перегрузка |
| 0x08 | Недопустимое состояние/неисправность сети |
| 0x10 | Неисправность датчика |
| 0x20–0x80 | Резерв |

Пример: если одновременно выставлены низкая АКБ (0x01) и перегрев (0x02), байт равен 0x03. Снятие бита перегрева не снимает запрет низкой АКБ.

Timer1 проверяет весь байт только на границе полного периода. Если запрет появился во время работы, пара A+B завершается, а следующий период не начинается.

## 12. Измерение аккумулятора

Первый модуль, управляющий байтом запретов, — измерение напряжения АКБ на ADC6:

- batteryVoltageCentiV хранит напряжение в сотых долях вольта: 1234 означает 12,34 В;
- один полный результат собирается из 16 отсчётов АЦП;
- четыре первых отсчёта после выбора внутренней опоры отбрасываются;
- АЦП использует внутреннюю опору ATmega328P, номинально 1,1 В;
- делитель АЦП установлен на /128, частота АЦП при 16 МГц составляет 125 кГц;
- преобразования выполняются асинхронно: основной цикл запускает одно преобразование и позднее проверяет готовность результата;
- между отдельными отсчётами выдерживается не менее 2 мс;
- первая серия завершается до разрешения генерации;
- последующие полные измерения начинаются примерно раз в секунду;
- при напряжении не выше BATTERY_GENERATOR_STOP_CV устанавливается BLOCK_BATTERY_LOW; запрет защёлкивается;
- повышение напряжения само по себе не снимает защёлку;
- снять батарейную защёлку можно только при подтверждённой сети и достижении BATTERY_GENERATOR_RECOVERY_CV;
- если оба порога равны нулю, батарейная отсечка временно отключена для макета;
- при некорректных порогах батарейный бит остаётся установленным;
- остальные биты generatorBlockFlags измерение АКБ не меняет.

Вся арифметика пересчёта напряжения выполняется целыми числами, без float; напряжение хранится в сотых долях вольта.

В качестве предварительного примера используется делитель 330 кОм (АКБ+ → ADC6) и 10 кОм (ADC6 → GND). При максимальном напряжении сборки напряжение на ADC6 должно оставаться с запасом ниже внутренней опоры 1,1 В. Номиналы делителя и опору необходимо откалибровать до подключения реальной батареи.

**Важно:** нулевые пороги не являются защитой аккумулятора. Перед эксплуатацией необходимо определить химию и номинальное напряжение батареи, откалибровать измерение и задать реальные пороги.

## 13. Реле зарядки и будущие пороги

Под управление реле зарядки выделен D8 / PB0 — сигнал `CHARGE_RELAY`, активный HIGH. Внешняя подтяжка к GND обязательна. В текущем скетче D8 настраивается как выход и остаётся LOW; алгоритм зарядки пока не включён. D8 выдаёт только логический сигнал на драйвер реле, катушку реле нельзя подключать непосредственно к выводу Nano.

В начале `ArduinoUPS.ino` зарезервированы параметры для будущего меню:
- `BATTERY_CHARGE_ON_CV` — порог включения зарядки при снижении напряжения;
- `BATTERY_CHARGE_OFF_CV` — порог выключения зарядки при повышении напряжения.

Сейчас оба значения равны нулю и не используются. Позже зарядное реле будет управляться с гистерезисом по этим порогам.

## 14. Очерёдность дальнейшей разработки

Работы выполнять поэтапно. Сначала довести до надёжной работы текущий макет; не начинать сложные функции, пока не проверена базовая силовая и управляющая часть.

### Ближайшие этапы

1. **Макет генератора и силовой части**
   - проверить форму и частоту управляющих сигналов;
   - проверить dead time, чередование плеч и безопасный запуск/остановку;
   - испытать драйверы и силовую часть на макете;
   - проверить измерение напряжения АКБ и базовые блокировки.

2. **Дисплей и энкодер**
   - подключить экран;
   - реализовать управление меню энкодером и отображение основных параметров;
   - предусмотреть настройку доступных параметров без перекомпиляции прошивки.

3. **Часы**
   - добавить часы реального времени (RTC);
   - использовать время для индикации и будущей статистики/журналирования.

4. **Контроль температуры**
   - подключить датчик температуры;
   - отображать температуру и использовать её для защиты от перегрева.

5. **Вентилятор с контролем вращения**
   - реализовать управление вентилятором;
   - подключить датчик тахометра и контролировать фактические обороты;
   - предусмотреть обнаружение остановки/неисправности вентилятора и соответствующую реакцию системы.

6. **Остальные функции и защиты**
   - управление зарядным устройством и реле;
   - измерение тока, контроль нагрузки и дополнительные защиты;
   - переключение сети/инвертора и прочие функции по мере готовности макета.

### Долгосрочная задача: слежение за сетью и синхронизация

После реализации и проверки более приоритетных функций отдельно спроектировать систему постоянного измерения сетевой частоты и фазы и плавной синхронизации внутреннего генератора с сетью.

Предварительная концепция:
- отдельный изолированный датчик сети на оптопаре формирует временные метки, связанные с переходами сетевого напряжения через ноль; возможный вариант датчика — H11AA1 с правильно рассчитанной входной цепью;
- микроконтроллер измеряет интервалы между метками, оценивает частоту и фазовое положение сети;
- внутренний генератор плавно подстраивает длительности будущих интервалов Timer1, используя оценку фазовой и частотной ошибки (цифровая ФАПЧ/PLL), без резких скачков периода;
- при пропадании сети генератор продолжает работу с последней достоверной оценкой частоты и текущей фазой, затем переходит к автономному поддержанию номинальных 50 Гц;
- после появления сети система проверяет устойчивость измерений и постепенно возвращает генератор к синхронизму, а не подстраивается скачком по первому импульсу;
- dead time, чередование плеч и симметричная остановка генератора должны сохраняться при любой подстройке.

Эта функция предназначена для будущего согласованного переключения между сетью и инвертором. Сама синхронизация не заменяет аппаратную блокировку одновременного соединения сети и инвертора, гарантированный разрыв перед переключением и контроль напряжений. Схему датчика, алгоритм ФАПЧ, допустимые ошибки/диапазоны и безопасную логику переключения необходимо отдельно рассчитать и проверить до подключения к реальной сети.

До этого этапа не менять ради синхронизации текущую распиновку и алгоритм генератора. Выделение отдельного входа для датчика сети и окончательное назначение выводов согласовать при проектировании соответствующего этапа.
