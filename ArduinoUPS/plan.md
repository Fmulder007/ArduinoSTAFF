# ArduinoUPS — RP2040-Zero / PIO + журнал OLED

**Статус:** испытательная версия: четыре выхода PIO, RUN, батарейная блокировка, USB Serial и журнал на OLED.  
**База:** ветка \`arduino-ups-rp2040-pio\`, перенесённая из \`arduino-ups-four-output-driver\`.  
**Текущая ветка:** \`arduino-ups-rp2040-log-display\`.  
**Плата:** Waveshare RP2040-Zero, RP2040.  
**Среда:** Arduino IDE + Arduino-Pico core by Earle F. Philhower.

## 1. Цель версии

Сохранить уже проверенный PIO-генератор и добавить:
- вход RUN;
- измерение напряжения АКБ;
- общий байт запретов \`generatorBlockFlags\`;
- защёлку низкого напряжения АКБ и восстановление;
- единый журнал событий на USB Serial и OLED 128×32.

Дисплей пока показывает только журнал. Часы DS1307 пока не подключены: дата/время формируются заглушкой \`--.--.---- --:--:--\`.

Файловый журнал во Flash и USB Mass Storage не используются.

## 2. Распиновка

| RP2040-Zero | Назначение |
|---|---|
| GP0 | DRIVER_A_H — верхнее плечо драйвера A |
| GP1 | DRIVER_A_L — нижнее плечо драйвера A |
| GP2 | DRIVER_B_H — верхнее плечо драйвера B |
| GP3 | DRIVER_B_L — нижнее плечо драйвера B |
| GP4 | RUN — HIGH: генерация нужна; LOW: сеть появилась |
| GP5 | Внутренняя аварийная связь PIO1 → PIO0; внешняя проводка не требуется |
| GP8 | I2C0 SDA — OLED сейчас, DS1307 позднее |
| GP9 | I2C0 SCL — OLED сейчас, DS1307 позднее |
| GP16 | Встроенный RGB-светодиод WS2812, UART0 TX + DMA |
| GP26 | ADC0 — измерение напряжения АКБ |
| GP27 | DRAIN_A_FB — цифровой датчик стока A |
| GP28 | DRAIN_B_FB — цифровой датчик стока B |

GP0–GP3 управляются PIO0 атомарно четырёхбитным side-set. GP4 читается только функцией `updateRunStatus()`. PIO1 SM0 в режиме GENERATION наблюдает за GP0/GP2 и считывает датчики GP27/GP28. GP5 — выход PIO1 и вход JMP PIN PIO0, полностью внутренняя связь на кристалле.

Датчики GP27/GP28 должны иметь внешние формирователи с определёнными уровнями 0/1, ограничением входного напряжения и защитой от отрицательных/положительных выбросов. Непосредственно силовые стоки к GPIO не подключать.

Энкодер и DS18B20 пока не подключаются. GP10–GP13 остаются свободными под будущую периферию.

## 3. Генератор PIO

Параметры сохранены из прежней четырёхвыходной версии:

- частота задаётся только `UPS_FREQUENCY_HZ`, сейчас 50 Гц;
- полный период при 50 Гц — 20 мс;
- активный интервал каждого плеча — 90% полупериода (9 мс при 50 Гц);
- общее межполупериодное окно — 10% полупериода (1 мс при 50 Гц);
- защитная пауза внутри каждого драйвера — 50 мкс;
- остаточное межфазное ожидание — 900 мкс при 50 Гц.

Частота PIO — 2,5 МГц, один такт — 0,4 мкс. При `clk_sys = 125 МГц` используется целый делитель 50.

PIO0 SM0 управляет GP0–GP3. Для компактности и одновременной смены четырёх выходов используется обязательный side-set шириной 4 бита. Программа занимает 29 из 32 инструкций PIO0. Во время каждого активного импульса A и B в коротком цикле выполняется `JMP PIN` по GP5; обнаружение внутреннего fault-сигнала переводит выходы в NORMAL и устанавливает PIO0 IRQ1.

PIO1 SM0 работает как независимый монитор датчиков стоков:
- ждёт фактического уровня команды A на GP0;
- через четверть периода считывает GP27 и GP28 одной инструкцией `IN PINS, 2`;
- затем ждёт завершения A и команды B на GP2;
- через четверть периода после команды B снова считывает оба датчика;
- единственная аварийная комбинация первой версии — оба датчика LOW (`00`);
- при `00` PIO1 устанавливает GP5, который PIO0 обнаруживает в своём активном цикле.

Аварийная последовательность:
1. PIO1 обнаруживает `DRAIN_A_FB=0` и `DRAIN_B_FB=0`.
2. PIO1 поднимает внутреннюю линию GP5.
3. PIO0 выполняет `JMP PIN` внутри активного импульса и переходит в аварийную ветвь.
4. Команда `IRQ SET 1 SIDE 1010` одновременно устанавливает NORMAL=1010 и PIO0 IRQ1. NORMAL=1010 — это включённые нижние входы драйверов; затворы обоих силовых MOSFET притянуты к земле.
5. Следующая команда PIO0 удерживает NORMAL бесконечно. PIO0 не ждёт окончания периода и не возобновляет генерацию самостоятельно.
6. CPU в `serviceGeneratorPioFault()` фиксирует `BLOCK_DRAIN_FAULT=0x20` в `generatorBlockFlags`, сбрасывает `generatorIsRunning`, отключает монитор и записывает событие в журнал.

CPU не участвует в первичном аварийном отключении. Он только обрабатывает IRQ уже после аппаратного перехода PIO0 в NORMAL. При аварии `generatorFaultLatched` блокирует повторное разрешение генерации до перезапуска контроллера.

### 3.1. Расчёт четверти периода

Полупериод и четверть периода рассчитываются из `UPS_FREQUENCY_HZ` и `PIO_CLOCK_HZ`, округлением к ближайшему целому такту. Все вычисления целочисленные; промежуточные произведения используют `uint64_t`.

`quarterPeriodTicks = round(PIO_CLOCK_HZ / (4 × UPS_FREQUENCY_HZ))`. В счётчике учтён один такт инструкции WAIT, синхронизирующей старт отсчёта по фронту GPIO.

Примеры при PIO 2,5 МГц:

| Частота | Четверть периода | Такты PIO |
|---:|---:|---:|
| 40 Гц | 6250 мкс | 15625 |
| 50 Гц | 5000 мкс | 12500 |
| 60 Гц | 4166,8 мкс | 10417 |
| 70 Гц | 3571,6 мкс | 8929 |

После изменения `UPS_FREQUENCY_HZ` четверть периода, полупериод и связанные задержки пересчитываются автоматически. Использование частот, при которых активный интервал не длиннее четверти периода, отвергается при инициализации.

PIO0 опрашивает GP5 в активном цикле с периодом около 0,8 мкс (две инструкции PIO). После поднятия GP5 аварийный NORMAL появляется на следующей инструкции PIO0. Эти интервалы относятся к цифровой логике; время реакции аналоговых датчиков и силовой части необходимо определить осциллографом.

## 4. Таблица состояний выходов

Бит 0 = GP0/A_H, бит 1 = GP1/A_L, бит 2 = GP2/B_H, бит 3 = GP3/B_L.

| Состояние | Биты GP3…GP0 | Включённые плечи |
|---|---:|---|
| NORMAL | 1010 | A_L + B_L |
| A_PREPARE | 1000 | B_L |
| A_ACTIVE | 1001 | B_L + A_H |
| B_PREPARE | 0010 | A_L |
| B_ACTIVE | 0110 | A_L + B_H |
| ALL_OFF | 0000 | все выключены |

Ни в одном состоянии верхнее и нижнее плечо одного драйвера не включаются одновременно. Все четыре бита изменяются одной командой PIO.

## 5. RUN и разрешение генерации

- RUN=HIGH означает запрос генерации.
- RUN=LOW должен сохраняться непрерывно 5000 мс, чтобы сеть считалась подтверждённой.
- Кратковременный RUN=LOW менее 5 секунд не снимает запрос генерации.
- При подтверждении сети запрос генерации снимается.
- Генерация разрешена только если \`generatorRunRequest == true\` и \`generatorBlockFlags == 0\`.
- `generatorIsRunning` — отдельный глобальный статус фактического выполнения периода PIO; он не является копией запроса RUN или разрешения.
- Обычный запрос STOP (IRQ0) исполняется на границе полного периода A+B. Авария датчиков стоков обрабатывается отдельным аппаратным путём: немедленный NORMAL внутри активного импульса, затем IRQ1.
- Если запрос снова разрешён, PIO начинает следующий полный период.

## 6. Байт запретов generatorBlockFlags

`generatorBlockFlags` — общая маска типа `uint8_t`:
- `0x00` — запретов нет, генерация может работать при RUN=HIGH;
- любое ненулевое значение — генерация запрещена;
- каждый модуль меняет только принадлежащий ему бит.

| Маска | Причина |
|---:|---|
| 0x01 | Низкое напряжение аккумулятора |
| 0x02 | Перегрев |
| 0x04 | Перегрузка |
| 0x08 | Неисправность/недопустимое состояние сети |
| 0x10 | Неисправность датчика |
| 0x20 | Авария датчиков стоков: одновременно GP27=0 и GP28=0 в контрольной точке |
| 0x40–0x80 | Резерв |

В этой версии реализованы батарейный бит 0x01 и аварийный бит датчиков стоков 0x20. Остальные причины пока зарезервированы.

Аварийный бит 0x20 выставляется только после того, как PIO0 уже перевёл GP0–GP3 в NORMAL и установил IRQ1. Обработка программной маски не является механизмом первичного отключения.

Батарейная логика:
- напряжение хранится в сотых долях вольта (`1234 = 12,34 В`);
- измерение выполняется раз в секунду;
- каждый результат — среднее 16 измерений;
- достижение нижнего порога защёлкивает `BLOCK_BATTERY_LOW`;
- само по себе повышение напряжения после снятия нагрузки не снимает защёлку;
- снятие защёлки разрешено только при подтверждённой сети и достижении порога восстановления;
- если оба порога равны нулю, батарейная отсечка временно отключена для макета;
- неправильно заданные пороги оставляют батарейную блокировку установленной.

АЦП RP2040 настраивается на 12 бит (0…4095). Используется номинальная опора 3300 мВ и делитель 330 кОм / 10 кОм. Пересчёт выполняется целочисленно; промежуточное умножение использует `uint64_t`. Коэффициент опоры нужно откалибровать по конкретной плате и мультиметру до эксплуатации.

## 7. Журнал событий

Все сообщения создаются одной функцией \`logEvent()\` и одновременно направляются:
- в USB CDC Serial;
- в буфер текстового журнала OLED.

Скорость, передаваемая в \`Serial.begin()\`, — 9600. Для USB CDC это параметр линии виртуального COM-порта; физический USB-поток не ограничивается UART-скоростью.

Дата/время пока выдаются заглушкой \`--.--.---- --:--:--\`. При добавлении DS1307 заменяется только функция \`getLogTimestamp()\`.

Логируются только изменения:
- запрос генерации и подтверждение сети;
- появление каждой причины блокировки;
- переход общей маски из 0 в ненулевое значение;
- восстановление напряжения и снятие батарейной защёлки;
- снятие отдельных причин запрета;
- переход общей маски обратно в 0.

Повторяющиеся сообщения в каждом проходе \`loop()\` не печатаются.

Примеры сообщений:

\`\`\`text
--.--.---- --:--:-- [BOOT] ArduinoUPS RP2040 запущен
--.--.---- --:--:-- [RUN] Запрошена генерация
--.--.---- --:--:-- [BLOCK] flags=0x01, Низкое напряжение аккумулятора
--.--.---- --:--:-- [BLOCK] flags=0x01, Генерация запрещена
--.--.---- --:--:-- [RUN] Сеть подтверждена
--.--.---- --:--:-- [RECOVERY] Напряжение аккумулятора восстановлено
--.--.---- --:--:-- [CLEAR] flags=0x00, Блокировка по низкому напряжению снята
--.--.---- --:--:-- [ALLOW] flags=0x00, Все запреты генерации сняты
\`\`\`

Событие обрабатывается только при изменении состояния. Если USB Serial Monitor не подключён, программа не ждёт его открытия; журнал продолжает поступать на OLED.

## 8. OLED 128×32

- Контроллер: SSD1306 128×32.
- I2C: первый аппаратный интерфейс RP2040, `Wire`, GP8/GP9.
- Частота I2C: 100 кГц; после `init()` скорость повторно задаётся через `Wire.setClock()`.
- Перед `Wire.begin()` выводы назначаются вызовами `Wire.setSDA(8)` и `Wire.setSCL(9)`.
- Адрес при старте проверяется сначала 0x3C, затем 0x3D.
- Библиотека: GyverOLED 1.6.4, SSD1306 128×32, программный буфер 512 байт, стандартный `Wire` (I2C0).
- Шрифт: встроенная таблица GyverOLED, поддержка русского текста и буквы «ё».
- На дисплее четыре текстовые строки высотой 8 пикселей.
- Длинные сообщения делятся приложением на строки по 21 символу без разрыва UTF-8 последовательностей.
- Новые строки добавляются снизу, старые уходят вверх.
- В RAM хранится 20 последних строк для формирования прокрутки.
- Обновление дисплея выполняется только после появления новых сообщений.
- Если OLED не обнаружен, журнал Serial продолжает работать.

Исходники GyverOLED 1.6.4 находятся локально в `src/libraries/GyverOLED/`; установка через Library Manager не требуется.

## 8.1. Встроенный RGB-индикатор состояния

На Waveshare RP2040-Zero встроенный адресный RGB-светодиод WS2812 подключён к GP16.

Для передачи цвета используется аппаратный UART0 TX с инверсией выходного сигнала GPIO и DMA:
- GP16 поддерживает функцию UART0 TX;
- выход GP16 инвертируется через GPIO output override;
- каждый бит WS2812 кодируется отдельным UART-символом 8N1;
- DMA передаёт 24 кодовых байта в TX FIFO UART0 по запросам DREQ_UART0_TX;
- CPU не формирует импульсы, не ожидает окончания кадра и не отключает прерывания;
- PIO0 и PIO1, их State Machine и память инструкций не используются светодиодом.

USB CDC `Serial` остаётся независимым от UART0. UART0 зарезервирован для WS2812; `Serial1` в проекте не используется.

При штатной частоте периферийной шины 125 МГц скорость UART составляет 7,8125 Мбит/с. Один UART-символ содержит 10 бит (start, 8 data, stop) и длится 1,28 мкс. После инверсии линии:
- код WS2812 `0`: `0xFC`, HIGH 384 нс, LOW 896 нс;
- код WS2812 `1`: `0xE0`, HIGH 768 нс, LOW 512 нс.

Кадр передаётся в порядке GRB, старшим битом вперёд. После окончания UART-передачи линия остаётся LOW; перед следующим кадром выдерживается интервал фиксации не менее 300 мкс. Состояние кадра и reset-интервала проверяются неблокирующе через `micros()`; рисунок мигания по-прежнему управляется через `millis()`.

Модуль `status_led.h` предоставляет:
- `initializeStatusLed()` — однократную настройку UART0 и выделение одного DMA-канала;
- `updateStatusLed()` — неблокирующее обновление рисунка индикации и запуск DMA-передачи при необходимости.

Состояние индикации определяется двумя глобальными флагами:
- `generatorBlockFlags` — маска причин запрета. Если она ненулевая, всегда показывается красный код ошибки; состояние генератора не влияет на красную последовательность.
- `generatorIsRunning` — фактическое состояние PIO-генератора. При нулевой маске блокировок выбирает зелёный или жёлтый цвет.

Индикация:
- `generatorBlockFlags != 0`: красный код из 1…8 вспышек соответственно установленным битам;
- `generatorBlockFlags == 0` и `generatorIsRunning == false`: зелёная вспышка длительностью 100 мс один раз в секунду;
- `generatorBlockFlags == 0` и `generatorIsRunning == true`: жёлтая вспышка длительностью 100 мс один раз в секунду;
- если установлено несколько битов, красные коды показываются последовательно по возрастанию номера бита;
- длительность красной вспышки — 100 мс, пауза между вспышками одного кода — 200 мс, между кодами — 600 мс, после полной серии — 1500 мс;
- изменение маски немедленно перезапускает соответствующий рисунок;
- изменение `generatorIsRunning` переключает зелёный/жёлтый рисунок только при нулевой маске блокировок и не влияет на текущую красную последовательность.

Если инициализация UART0 или DMA не удалась, индикация отключается, но работа генератора не затрагивается.

## 9. Локальные зависимости и воспроизводимая сборка

GyverOLED 1.6.4 хранится непосредственно в `src/libraries/GyverOLED/` вместе с исходниками, `library.properties`, README и лицензией MIT. Скетч подключает локальный заголовок относительным путём; устанавливать библиотеку через Library Manager не требуется. Используется стандартный `Wire` Arduino-Pico, поэтому отдельная библиотека I2C не нужна.

## 10. Целочисленная арифметика

В пользовательском коде не использовать \`float\` и \`double\`.

- напряжение АКБ — сотые доли вольта;
- частота — целое число герц;
- временные интервалы — целое число тактов PIO или миллисекунд;
- температура будущего DS18B20 — сотые доли градуса;
- причины блокировки — байтовая маска;
- коэффициенты делителей и опорные напряжения — целые числа;
- промежуточное умножение при расчёте напряжения — \`uint64_t\`.

## 11. Что пока не реализовано

- DS1307 и реальная дата/время;
- энкодер;
- DS18B20;
- меню и другие экраны;
- синхронный выпрямитель STANDBY с перекрёстным управлением по GP27/GP28; перед вводом требуется определить максимальное время открытого MOSFET при зависшем уровне датчика и проверить переключение владения GP0–GP3 между PIO0 и PIO1;
- реле зарядки;
- остальные аппаратные защиты;
- файловый журнал во Flash;
- USB Mass Storage.

## 12. Проверка на стенде

1. Собрать скетч для Waveshare RP2040-Zero с CPU 125 MHz.
2. Использовать локальную GyverOLED 1.6.4 из `src/libraries/GyverOLED/` — внешняя установка библиотеки не нужна.
3. Без силовых драйверов проверить стартовые GP0–GP3: на выводах должно быть NORMAL=1010 ещё до разрешения RUN.
4. Проверить GP0–GP3 осциллографом; убедиться, что PIO-сигналы сохранили последовательность, активные интервалы и междрайверные паузы.
5. Проверить вход RUN: HIGH запускает, LOW менее 5 секунд не останавливает.
6. Удерживать RUN=LOW 5 секунд: генератор завершает полный A+B и возвращается в NORMAL.
7. Проверить русские сообщения, включая «ё», в Serial Monitor и на OLED.
8. Проверить зелёную вспышку при отсутствии блокировок и остановленном генераторе; жёлтую — при работающем генераторе; красные коды — для каждого установленного бита.
9. На низковольтном стенде проверить датчики стоков: после команды A через четверть периода должны быть ожидаемые уровни, затем то же после команды B. Подать тестовую комбинацию 00 и подтвердить осциллографом, что PIO0 переводит GP0–GP3 в NORMAL до обработки IRQ процессором.
10. Проверить четверть периода для 40, 50 и 60 Гц; убедиться, что счётчики рассчитываются целочисленно.
11. Временно задать тестовые пороги батареи и проверить установку/снятие `BLOCK_BATTERY_LOW`.
12. Проверить, что OLED, Serial и UART0+DMA светодиода не нарушают временную последовательность GP0–GP3.

Силовые драйверы подключать только после проверки логических сигналов датчиков, аварийного перехода в NORMAL и всех защитных интервалов.
